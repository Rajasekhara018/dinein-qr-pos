# UAM External Auth Provider Configuration

This module starts with no external auth provider enabled. In the default mode, UAM authenticates users through its local auth flow and issues local JWT tokens.

## Default Mode: No External Provider

Default configuration:

```properties
railcab.uam.identity-provider.enabled=false
railcab.uam.identity-provider.type=none
railcab.uam.identity-provider.token-validation=local
```

Equivalent environment variables:

```bash
UAM_IDENTITY_PROVIDER_ENABLED=false
UAM_IDENTITY_PROVIDER=none
UAM_IDENTITY_TOKEN_VALIDATION=local
```

Behavior:

- `/auth/login` uses the local UAM user store.
- Tokens are generated by UAM as local JWT tokens.
- API requests are validated by `JwtAuthenticationFilter`.
- `/auth/provider/login`, `/auth/provider/refresh`, and `/auth/provider/logout` route to the `none` provider and fail fast instead of calling Keycloak/OIDC.
- User, role, permission, group, client, and organization sync operations route to the no-op sync adapter.

Use this mode for local development, standalone UAM deployments, and deployments where another gateway handles external authentication before traffic reaches UAM.

## Provider Selection

Provider routing is controlled by:

```properties
railcab.uam.identity-provider.enabled=true
railcab.uam.identity-provider.type=keycloak
```

Supported provider type values are defined by `IdentityProviderType`:

| Type | Purpose |
| --- | --- |
| `none` | No external auth provider. |
| `keycloak` | Keycloak login, refresh, logout, and admin sync. |
| `oidc` | Generic OIDC token flow. Sync is unsupported unless an adapter is added. |
| `okta` | Placeholder type for provider-specific implementation. |

When `railcab.uam.identity-provider.enabled=false`, the router forces `none` even if a request sends a provider type.

When `railcab.uam.identity-provider.enabled=true`, provider auth uses the request `providerType` if present. If the request does not include `providerType`, it falls back to `railcab.uam.identity-provider.type`.

## Token Validation Modes

UAM supports two validation modes:

| Value | Behavior |
| --- | --- |
| `local` | Validate UAM-issued JWTs with `JwtAuthenticationFilter`. |
| `jwt` | Validate external provider JWTs with Spring OAuth2 resource server. |

Default:

```properties
railcab.uam.identity-provider.token-validation=local
```

Use external JWT validation only when the selected provider issues the access token consumed by UAM APIs:

```properties
railcab.uam.identity-provider.enabled=true
railcab.uam.identity-provider.token-validation=jwt
spring.security.oauth2.resourceserver.jwt.issuer-uri=https://provider.example.com/realms/railcab
```

## Keycloak Setup

Use Keycloak when UAM should delegate provider login and provision identity objects into Keycloak.

```bash
UAM_IDENTITY_PROVIDER_ENABLED=true
UAM_IDENTITY_PROVIDER=keycloak
UAM_IDENTITY_TOKEN_VALIDATION=jwt

KEYCLOAK_SERVER_URL=http://localhost:8180
KEYCLOAK_REALM=railcab
KEYCLOAK_CLIENT_ID=railcab-uam
KEYCLOAK_CLIENT_SECRET=change-me
KEYCLOAK_ADMIN_USERNAME=admin
KEYCLOAK_ADMIN_PASSWORD=admin-password
KEYCLOAK_ISSUER_URI=http://localhost:8180/realms/railcab
```

Configuration keys:

```properties
railcab.uam.keycloak.server-url=${KEYCLOAK_SERVER_URL:http://localhost:8180}
railcab.uam.keycloak.realm=${KEYCLOAK_REALM:railcab}
railcab.uam.keycloak.client-id=${KEYCLOAK_CLIENT_ID:railcab-uam}
railcab.uam.keycloak.client-secret=${KEYCLOAK_CLIENT_SECRET:}
railcab.uam.keycloak.admin-username=${KEYCLOAK_ADMIN_USERNAME:}
railcab.uam.keycloak.admin-password=${KEYCLOAK_ADMIN_PASSWORD:}
```

Expected behavior:

- `/auth/provider/login` calls the Keycloak token endpoint.
- `/auth/provider/refresh` calls the Keycloak token endpoint with refresh token grant.
- `/auth/provider/logout` calls the Keycloak logout endpoint.
- Identity sync operations use Keycloak admin APIs.
- If `token-validation=jwt`, UAM validates Keycloak-issued access tokens.

## Generic OIDC Setup

Use `oidc` when the provider supports standard OIDC token endpoints but does not require provider-specific admin sync.

```bash
UAM_IDENTITY_PROVIDER_ENABLED=true
UAM_IDENTITY_PROVIDER=oidc
UAM_IDENTITY_TOKEN_VALIDATION=jwt

OIDC_ISSUER_URI=https://issuer.example.com
OIDC_TOKEN_URI=https://issuer.example.com/oauth2/token
OIDC_LOGOUT_URI=https://issuer.example.com/oauth2/logout
OIDC_REVOCATION_URI=https://issuer.example.com/oauth2/revoke
OIDC_CLIENT_ID=railcab-uam
OIDC_CLIENT_SECRET=change-me
OIDC_SCOPE="openid profile email"
OIDC_AUDIENCE=railcab-api
```

Configuration keys:

```properties
railcab.uam.oidc.issuer-uri=${OIDC_ISSUER_URI:}
railcab.uam.oidc.token-uri=${OIDC_TOKEN_URI:}
railcab.uam.oidc.logout-uri=${OIDC_LOGOUT_URI:}
railcab.uam.oidc.revocation-uri=${OIDC_REVOCATION_URI:}
railcab.uam.oidc.client-id=${OIDC_CLIENT_ID:}
railcab.uam.oidc.client-secret=${OIDC_CLIENT_SECRET:}
railcab.uam.oidc.scope=${OIDC_SCOPE:openid profile email}
railcab.uam.oidc.audience=${OIDC_AUDIENCE:}
```

Expected behavior:

- Provider login supports password and authorization-code style token requests.
- Refresh uses the refresh token grant.
- Logout uses the revocation/logout endpoint when configured.
- Identity sync operations are unsupported by the generic OIDC adapter.

## Sync Behavior

Domain changes such as users, roles, permissions, groups, clients, and organizations go through `IdentityProviderSyncRouter`.

The sync router selects the adapter using:

```properties
railcab.uam.identity-provider.enabled=true
railcab.uam.identity-provider.type=keycloak
```

Unsupported sync behavior is controlled by:

```properties
railcab.uam.identity-provider.unsupported-sync-action=fail
```

Allowed values:

| Value | Behavior |
| --- | --- |
| `fail` | Throw an error when the selected provider does not support the operation. |
| `skip` | Ignore unsupported sync operations. |

For enterprise deployments, prefer `fail` in environments where identity consistency is required. Use `skip` only when the provider is intentionally auth-only and UAM remains the source of truth for roles and permissions.

## Adding Another Provider

To add another auth provider with minimal changes:

1. Add a provider type to `IdentityProviderType`.
2. Implement `IdentityProviderAuthService`.
3. Return the enum from `providerType()`.
4. Add provider-specific configuration under `UamProperties` and `application.properties`.
5. If the provider supports provisioning, implement `IdentityProviderSyncAdapter`.
6. Implement `supports(IdentityProviderSyncOperation operation)` honestly for the provider capabilities.

The routers do not need provider-specific `if/else` logic. Spring discovers provider beans and the routers select the correct adapter by `IdentityProviderType`.

## Recommended Production Defaults

For standalone UAM with local JWTs:

```bash
UAM_IDENTITY_PROVIDER_ENABLED=false
UAM_IDENTITY_PROVIDER=none
UAM_IDENTITY_TOKEN_VALIDATION=local
JWT_SECRET=<strong-256-bit-secret>
```

For external identity provider with provider-issued JWTs:

```bash
UAM_IDENTITY_PROVIDER_ENABLED=true
UAM_IDENTITY_PROVIDER=keycloak
UAM_IDENTITY_TOKEN_VALIDATION=jwt
KEYCLOAK_ISSUER_URI=https://id.example.com/realms/railcab
```

Keep client secrets, admin passwords, JWT secrets, and issuer URLs outside source control and inject them through environment variables or a secret manager.
